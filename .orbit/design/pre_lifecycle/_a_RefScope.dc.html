Scope map

Every board in this file belongs to one of three groups. Only the first group is custom UI/UX that the fork has to build. The other two exist to check a view or to explain a model.

Default rule. Anything in Grafana that these boards do not change stays exactly as Grafana ships it. The list of what changes is on R01 · Change list.
Custom

Custom UI/UX

Built in the fork. These parts replace or extend the Grafana chrome.

  • Frame and top bar
  • Floating dock and its states
  • Menu sheet: page list, sub page tiles, group tabs
  • App switcher, user menu, add menu
  • Breadcrumb component
  • Apps and bookmark pages views
  • App manage and app lifecycle views, with the checks list
  • Apps row, app lifecycle statuses and version info
Grafana sample

Grafana sample, view check only

Grafana's own content, placed inside the custom chrome to judge how it looks. Not redesigned, not built. Nothing in these bodies is a new component.

  • Home body: Welcome to Grafana, starred and recent dashboards, blog
  • Dashboard body: variables, time controls, panels, table, dashboard sidebar
Reference page

Reference pages

Explain a model. They are specs, not product screens.

  • Breadcrumb states: every breadcrumb type the project can use
  • App manifest draft: how an app model manifest is described

Terms: apps, pages, sub pages, tabs

Decided 2026-11-06. Bookmarks follow Grafana's nav tree: any nav item with a URL can be bookmarked, so pages and sub pages can, and apps and tabs cannot. The word “sub-section” is no longer used.

TermWhat it is in GrafanaBookmarkableExample
AppAn app plugin (type: app, nav section plugin-page-<id>) or a built-in app: Monitoring is Grafana's own sections.No. Open <app> opens its home page: the defaultNav page, Home for Monitoring.Maintenance, Monitoring
PageA nav item directly under the app: an includes[] page with addToNav, or a Grafana section.YesWork orders, Dashboards
Sub pageA nav item under a page: a Grafana child, or an app include whose path sits under the page path (nested by grafana.pluginPathNesting). A sub page may have its own sub pages, shown as groups.Yes, with its own toggleWork orders › Open, Dashboards › Playlists
TabA tab inside a page (pageNav children), not a nav item. The MenuSheet group tabs (S10) are a menu control, not page tabs.No. A tab belongs to its pageAlert rule › History
BookmarkA page or sub page URL in navbar.bookmarkUrls. The dock label of a sub page reads Page › Sub page.–Reports › Weekly

What the source check says

Read in the Grafana v13.3.0 source tag. The main branch at the time was 13.4.0-pre, so the tag was checked out separately. Verified means the code was read, not that it was run.

Verified in v13.3.0

Chrome slots are closed to other plugins

The extension points grafana/app/chrome/v1, grafana/megamenu/action and grafana/singletopbar/action only render components from plugin grafana-setupguide-app. A normal plugin cannot draw into them. Other plugin-only techniques were not evaluated.

AppChromeExtensionPoint.tsx, MegaMenuExtensionPoint.tsx, TopBarExtensionPoint.tsx, core/constants.ts

Verified in v13.3.0

The docked menu is one component inside AppChrome

AppChrome.tsx renders MegaMenu when docked (320px, auto-docked at 1200px and up) and AppChromeMenu otherwise. The dock replaces that branch.

AppChrome.tsx, MegaMenu.tsx (MENU_WIDTH), useResponsiveDockedMegaMenu

Verified in v13.3.0

Pinning already exists

usePinnedItems reads the user preference navbar.bookmarkUrls. Customising the menu is behind the flag grafana.customizableMegaMenu. Bookmarks use this store (decided 2026-11-06); grouping per app is derived from the URL.

MegaMenu/hooks.ts, featuremgmt/registry.go

Verified in v13.3.0

Apps are nav sections

App plugins become sections with id plugin-page-<pluginId> and url /a/<pluginId>; the app list is sorted by name. This fits the app model; the manifest draft decides how a second app declares itself.

navtreeimpl/applinks.go (addAppLinks, processAppPlugin)

Verified in v13.3.0

Unknown plugin.json keys are not rejected by the backend

ReadPluginJSON decodes without DisallowUnknownFields, but the published plugin.schema.json sets additionalProperties: false, so schema validators will complain about a ui block. Whether the key reaches the frontend is not verified.

pkg/plugins/plugins.go, docs/sources/developers/plugins/plugin.schema.json

Verified in v13.3.0

Page actions go to the chrome, not the page

Dashboards push their toolbar through AppChromeUpdate into chrome.update({ actions }); SingleTopBar renders it. The custom top bar has no slot for it and the Dashboard sample draws these buttons in the body.

AppChromeUpdate.tsx, SingleTopBar.tsx, NavToolbarActions.tsx
