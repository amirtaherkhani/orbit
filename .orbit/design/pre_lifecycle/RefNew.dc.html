Features

App model

Custom

An app is a named group of pages with an icon, an accent colour and its own dock pages. Monitoring is the built-in app (Grafana’s own sections); every other app is an app plugin.

Where: Everywhere the app shows: dock workspace button, app switcher, sheet rail, breadcrumb chip, Add app view

Grafana gives us

  • App plugins (type: app) with includes[] pages, addToNav, defaultNav; each becomes a nav section plugin-page-<id> at /a/<id> Verified in v13.3.0
  • Org-level plugin settings with Enabled and Bookmarked (pluginsettings models) Verified in v13.3.0

To build

  • Fields Grafana has no place for: accent, show in menu, show in dock selector and page descriptions (the ui block on the manifest board). Sub pages come from includes nested by path (grafana.pluginPathNesting, experimental)
  • A rule for “initialized”. Proposal: the org plugin setting is enabled and the plugin loaded without error
  • Built-in app: a fixed entry “Monitoring” that maps to Grafana’s core sections, not to a plugin

Open

  • ui inside plugin.json (schema says additionalProperties: false) or a separate file
  • Order of apps in the selector
  • Per user or per organisation

Spec: S13 · AppManifest: ui block draft (spec), R10 · AppsView and DockPagesView

App switcher

Custom

Chooses the active app. Opens from the dock workspace button and from the app button in the sheet rail.

Where: Dock popover (320×293) and sheet dropdown (276 wide)

Grafana gives us

  • Nothing comparable in the chrome. The scopes selector is a different feature Inferred

To build

  • List: one row per app shown in the selector, current app checked, “New” badge, an “Apps” row that opens the Apps page (/apps) directly
  • Switching sets the active app: dock pages group, sheet rail sections, breadcrumb chip and accent variables follow it
  • Active app source. Proposal: derive it from the route (/a/<id> = that app, everything else = Monitoring) and remember the last one per user

Open

  • When the “New” badge disappears (first open, or after N days)
  • What happens on a shared link to another app’s page

Spec: R09 · Overlays, S06 · AppSwitcher: open

Dock and bookmarks

Custom

Floating bar at the bottom: workspace button, Home (always there), Grafana items, one bookmarks group with the bookmarks of the active app (it follows the app switch), an add slot, Menu.

Where: Bottom of every page, 803×58 at 1440 wide, 17px from the bottom

Grafana gives us

  • Bookmarks exist as the user preference navbar.bookmarkUrls; the stored type is only BookmarkUrls []string Verified in v13.3.0
  • Bookmarks section /bookmarks for signed-in users; the page shows only URLs that match a nav item Verified in v13.3.0
  • User storage userstorage.grafana.app (per-user key–value, used by core through useUserStorage) Verified in v13.3.0

To build

  • Bookmarks per app (derived from the URL). Order is the order of navbar.bookmarkUrls; “show in dock”, dock label, “show the name” and added date live in user storage custom-bookmarks, so no backend change (proposal, see R10)
  • Our bookmarks page at /bookmarks is DockPagesView (S11): App filter, edit icon per card, Edit bookmark tab with dock settings
  • Bookmarks group in the accent of the active app (decided 2026-11-06)
  • Selected state follows the route; a page that is not bookmarked selects nothing (proposal)

Open

  • Maximum bookmarks in the dock: 6 per app with a “dock is full” warning is proposed in S20 (to confirm)
  • Keyboard model (tab stops or roving tabindex)
  • Bookmarks and dock: one store. Decided 2026-11-06: the dock shows bookmarks

Spec: R07 · Dock

Menu sheet

Custom

Replaces the left menu. Rail of the active app’s pages, tiles for the sub pages of the current page, the page’s own bookmark in the header, group tabs for Administration, footer with the focused item and key hints.

Where: Opens above the dock, 1080×436

Grafana gives us

  • Nav tree sections and children with text, icon, url, subTitle; MegaMenu hides isCreateAction children Verified in v13.3.0
  • Administration groups General, Plugins and data, Users and access Verified in v13.3.0

To build

  • Tile layout (6 columns), bookmark toggle on each sub page tile, page bookmark toggle in the header, count per page, page without sub pages state
  • Keyboard inside the sheet: arrows, Enter, B, Esc, scoped to the open sheet

Open

  • Labels that differ from Grafana (“Access”, “Shared dashboards”, footer copy): keep Grafana’s text or override
  • Focus on open and return on close

Spec: R08 · MenuSheet anatomy

Add app view

Custom

Lists registered apps and sets where each appears: menu, dock selector, or both.

Where: New route (proposal: /apps), opened from the app switcher “Apps” row

Grafana gives us

  • Plugin catalog and plugin settings pages exist; app plugins can be enabled per org Verified in v13.3.0

To build

  • Filter All / Added / Available, search, card grid with states Added, Available, Needs setup. One icon toggle at the top right adds (plus) or removes (check) at once; the meta row with status icons sits at the card bottom; actions Manage and Setup
  • Preview panel: two switches and a live preview of the selector and the menu, Cancel + Add
  • Write path for the choice (see App model: per user or per org)

Open

  • Who may add an app (role)
  • Route name and breadcrumb
  • Remove: the card toggle and “Remove from apps” on the manage view do the same (proposal, to confirm)

Spec: R10 · AppsView and DockPagesView, S17 · AppSwitcher: Apps row, S18 · AddAppFlow, S12 · AppsView: all apps

Bookmark pages view

Custom

Bookmarks pages and sub pages of any app; the dock shows the active app's bookmarks. The app home is always in the dock, so it is not a bookmark, and tabs inside a page are not either.

Where: Route /bookmarks (replaces Grafana’s page component, frontend only), opened from the dock Bookmarks button and “Manage bookmarks” in the add-bookmark popover (S20)

Grafana gives us

  • navbar.bookmarkUrls for storing bookmarked URLs Verified in v13.3.0

To build

  • Same pattern as Add app: filter All / Bookmarked / Available, cards with one top-right bookmark toggle that acts at once (filled = bookmarked, outline = available), “In dock” and “In the menu” status icons, preview with “Bookmark” and “Always show the name”
  • Writes Grafana’s bookmark list and the bookmark details in user storage, described under Dock

Open

  • Reorder from this view or by drag in the dock
  • Bookmarks for pages a user loses access to

Spec: R10 · AppsView and DockPagesView, S11 · DockPagesView: bookmark pages

Add-bookmark popover

Custom

The dashed “+” at the end of the dock bookmarks group opens a glass popover for the active app: search, All / Bookmarked filter, the app’s pages and sub pages with bookmark toggles, dock capacity and “Manage bookmarks”. The new bookmark drops into the dock.

Where: Popover above the dock “+” slot, no route. S20 · DockBookmarkAdd

Grafana gives us

  • Toggletip, FilterInput, RadioButtonGroup, Alert in @grafana/ui Verified in v13.3.0
  • navbar.bookmarkUrls as the store Verified in v13.3.0

To build

  • App accent on the slot, rows, hovers and capacity slots; shared overlay glass (R09)
  • Live search over page name, description and group; “No pages match” state
  • Landing motion in the dock, off with prefers-reduced-motion

Open

  • Cap of 6 bookmarks per app (proposal) and the “dock is full” rule
  • Esc, click outside and arrow keys are specified, not wired on the board
  • “App needs setup” state is described, not drawn

App pages in the menu sheet

Custom

Picking an app from the dock app button or the sheet app button shows that app’s pages in the MenuSheet: pages in the rail with counts, sub page tiles with bookmark toggles, the page bookmark in the header, loading and empty states. The dock does not change.

Where: MenuSheet, no route. S19 · MenuSheet: pages of the selected app

Grafana gives us

  • App pages from plugin.json includes[] (addToNav, defaultNav, role) Verified in v13.3.0

To build

  • Same rail items and tiles as Monitoring, in the app accent
  • “New” only on the most recently installed and activated app in the app dropdown

Open

  • Where page descriptions come from (ui.pages.<id>.description, proposal)

App manage view

Custom

One added app: where it appears, its pages, how it looks, and whether its configuration is healthy.

Where: New route (proposal: /apps/<id>), opened from Manage on the app card

Grafana gives us

  • App plugin pages from includes[] with role and addToNav Verified in v13.3.0
  • A plugin settings page per plugin (linked as Plugin settings) Inferred

To build

  • Where it appears: Menu and Dock app selector switches, each showing the manifest default
  • Pages table: path, who can open, sub pages, menu, check result, bookmark toggle
  • Appearance (accent, tile icon), read only
  • Reset to app defaults, Remove from apps

Open

  • Per user or per organisation for “Where it appears” (the board assumes the bookmark rule: org default, user override)
  • Who may remove an app

Spec: R10, S15 · AppManageView: manage app

App setup view

Custom

Guides an app that is installed but not initialized through the steps it needs.

Where: New route (proposal: /apps/<id>/setup), opened from Setup on a Needs setup card

Grafana gives us

  • Per-org plugin enable setting Verified in v13.3.0
  • Apps can ship their own configuration pages Inferred

To build

  • Four ordered steps: Installed, Enable for this organisation, Configure the app, Check the configuration
  • Step status Done, To do, Waiting, Failed; each failed check names its fix
  • Right panel: why the app is missing, last status, what happens after setup

Open

  • How the fork embeds or links the app’s own configuration page
  • Non-admin users: hide the view or show it read only

Spec: R10, S16 · AppSetupView: set up app

Configuration check

Custom

Checks that an app and each of its pages are ready, and says what to fix.

Where: Manage view (app section and Pages table) and setup view (step 4)

Grafana gives us

  • Plugin settings and health endpoints (/api/plugins/<id>/settings, /health) Inferred; health may need a backend plugin
  • Nav tree tells whether a user can see a page Verified in v13.3.0

To build

  • App checks: enabled for the org, loads without error, manifest ui block valid, accent readable, pages
  • Page checks: route responds, in the nav tree for the user, who can open, manifest page entry
  • Results Passed, Warning, Failed, Not run, each with its own mark shape; runs on open, after Save, after an update, and on Run check

Open

  • Whether a failed page is hidden from the dock and the menu (proposal)
  • How “route responds” is tested without running the page; likely the app reports its own pages
  • Where results are stored and for how long

Spec: R10 (Configuration check), S15, S16

Add app from a link, app updates

Custom

Adds an app from a Git repository link or a .zip link, checks it against this Grafana, and keeps it up to date. Apps is one list of the installed apps, not grouped by source.

Where: add-app flow (S18; under review), version info in the manage view (S15)

Grafana gives us

  • dependencies.grafanaDependency in plugin.json, a semver range Inferred
  • The running version in config.buildInfo.version Inferred
  • Installed app version in info.version Verified in v13.3.0
  • A plugin install API for the configured catalog; installing from any other URL Not verified
  • Unsigned plugins load only when listed in allow_loading_unsigned_plugins Inferred

To build

  • Link format (proposal): grafana-app:<host>/<owner>/<repo>[@range] or a plain .zip URL. No apps repository index
  • Checks before add and before every update: link, release, app plugin, Grafana range, installed version, checksum, signature, manifest
  • Version information only (installed, latest, compatibility, last checked); updating stays with grafana-cli or the plugin catalog

Open

  • Server-side component for download, install and private-repository tokens (backend escalation)
  • Whether unsigned apps are allowed at all
  • Restart or reload needed after install or update
  • Who may add and update apps (proposal: org admins)

Spec: R10, S17 · AppSwitcher: Apps row, S18 · AddAppFlow: check, S15 · AppManageView

Breadcrumb extensions

Custom

App chip as the first crumb, a dropdown on the current crumb with sibling pages, “…” collapse for long paths.

Where: Own 36px row above the page

Grafana gives us

  • buildBreadcrumbs data; Breadcrumb type { text, href, highlightText?, icon? }; no dropdown, no collapse, icon not rendered Verified in v13.3.0

To build

  • App chip with the app accent and icon
  • Siblings menu built from the parent nav item’s children
  • Collapse rule and a way to reach hidden levels

Open

  • Buttons or links for steps (links keep open-in-new-tab)

Spec: R11 · AppBreadcrumb: component, R06 · AppShell

Date and clock

Custom

Large local time in the top bar for shop-floor screens.

Where: Top bar, after the logo

Grafana gives us

  • No clock in Grafana’s chrome Inferred

To build

  • Antonio 600 46px digits, blinking colon (off under reduced motion), 3px progress bar, two-line date
  • Self-hosted Antonio font

Open

  • Time zone source
  • What the bar measures
  • 12 or 24 hours

Spec: R05 · Foundations (Clock)

App accent theming

Custom

Per-app colour set on the inner panel: accent, hover and selected fill, text.

Where: Inner panel data-app attribute, read by custom parts only

Grafana gives us

  • Grafana theme has one primary and one accent; no per-section colours Verified in v13.3.0

To build

  • CSS variables --hac, --hbg, --htx per app, taken from the manifest accent
  • Contrast check for any accent a plugin declares

Open

  • Fallback when a plugin declares no accent
  • Should Grafana content ever use the app accent (by the default rule: no)

Spec: R05 · Foundations (App accents)

Glass layer

Custom

Translucent surface with backdrop blur for the dock, sheet and custom menus.

Where: Custom overlays only

Grafana gives us

  • No blur surfaces in the Grafana theme Inferred

To build

  • Fill about 55–62% + blur 16–20px, solid fallback via @supports not (backdrop-filter)

Open

  • Safari, Firefox and low-end GPU check
  • prefers-reduced-transparency

Spec: R04 · Tokens (Glass)

Work outside the UI. One item needs a backend change: the custom-avatar flag (computed by the avatar cache but not exposed). The app ui fields ship as ui.json next to plugin.json, read from the plugin’s static route, and bookmark details live in Grafana’s user storage next to the unchanged navbar.bookmarkUrls list (decided 2026-11-06), so neither changes the backend.
