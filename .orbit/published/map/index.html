One import line decides who draws Grafana's frame

The new UI lives in new files under one name, orbit, and stock Grafana stays as shipped. The fork swaps the shell at a single import, and every page keeps working because pages talk to the shell through the state they already write. On the server, one isolated module keeps the app lifecycle.

Required upstream edits: 3, all in the seam list: SM01 (frontend, one line), SM13 and SM14 (backend module, an import and one line each). Optional: SM06, one line. Backend: one module, pkg/orbit. Based on Grafana v13.3.0, read but not yet built.

Seven layers, one direction of dependency

Each layer has one job and a main pattern, and the pattern names what it protects against. Imports point down. Only L5 may import Grafana internals, so a Grafana rename costs one adapter file and one contract test. The backend lane uses Grafana's existing APIs, plus one module of our own for the app lifecycle.

Adding a new concept

A concept is anything new the product should have: an app, a page, a shell feature, a metadata field, a setting, a rule. Decide where it lives before writing code. Answer the questions; the tree lights up your path.

The same procedure for every concept

  1. ClassifyUse the tree. Write five lines in the pull request: the concept, the layer, where its data lives, which seams it touches, how it is deleted.
  2. Name the contract firstIf it reads Grafana state, add a function in orbit/upstream and its contract test before any view code.
  3. Define the data shapeTypes plus a hand-written parser. No as, no any. Invalid input gives defaults and one warning.
  4. Build bottom-upHook in L4, then the view in L2 or L3, from @grafana/ui and theme tokens, checked against the Grafana UI Storybook. Strings through t(). Effects safe under StrictMode.
  5. Register through an existing seamOnly if none fits, add a seam, list it in .orbit/seams.json with maxChangedLines, and justify it. This is the only step that adds conflict surface.
  6. TestContract test for the ACL function, unit test for the parser and resolver, a component test in StrictMode; Go tests for anything in pkg/orbit.
  7. Run the guardsSeam allow-list, import boundaries, namespace and AI-file checks, the deletable check, lint, typecheck, Jest.
  8. Update the docsThe traceability table, the seam table if it changed, .orbit/CHANGELOG.md, and the Orbit API version if apps see the change.

One name, three versions, two sets of AI files

The fork has to survive every upstream upgrade. Three rules keep our files apart from Grafana's: one name for everything we add, version numbers that never touch Grafana's own, and agent files that live only in our folders.

One name: orbit

One search finds all our code, nothing upstream is called orbit (checked in v13.3.0 and on main), and deleting the orbit paths gives stock Grafana again. The earlier name custom matched 1,899 Grafana files.

  • .orbit/fork tooling, VERSION, COMPAT.md, CHANGELOG.md, docs, CI guards
  • public/app/orbit/frontend overlay
  • pkg/orbit/backend module
  • orbitthe product branch; Grafana version = base in seams.json
  • v13.3.0+orbit.4git tag; Docker 13.3.0-orbit.4
  • [orbit] [orbit.apps] [orbit.audit]grafana.ini sections; auto_migrate
  • orbit_app_lifecycletables, prefix orbit_
  • /api/orbit/…HTTP API of the backend module
  • orbit-bookmarksuser storage service

Three version numbers, kept apart

WhatFormatExampleWhere and why
Grafanaupstream, unchanged13.3.0Upstream tag. Never changed: Grafana sends it to the plugin catalog to pick compatible plugins (client.go:218-219).
Fork releasev<upstream>+orbit.<n>v13.3.0+orbit.4Git tag. Docker: 13.3.0-orbit.4. n starts at 1 again on each upstream tag.
Orbit APISemVer1.4.0.orbit/VERSION. Major when apps or users break. Apps declare requires.orbit.
Each appits own SemVer0.4.0plugin.json info.version, with grafanaDependency checked by Grafana.

Why +orbit and not -patch: in SemVer, anything after - is a pre-release and sorts before 13.3.0; anything after + is build metadata. Docker tags cannot hold +, so images use -orbit. Each release adds a row to .orbit/COMPAT.md.
