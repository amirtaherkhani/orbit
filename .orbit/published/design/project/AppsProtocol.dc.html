App manifest, draft

What the Apps view, the app lifecycle, the dock and the menu need to read from each app. Example values are placeholders. Fields marked Exists were checked against Grafana's plugin.json reference; fields marked New are proposals.

1Installgrafana-cli installs the app plugin. It ships a manifest; today that is its plugin.json.
2DiscoverAfter a restart Grafana loads the app. Apps lists it as Not initialized.
3PrepareInitialize, review, setup, validation and migration read the manifest.
4EnableThen per app: show in the menu, in the dock selector, or both.
5RenderDock switcher, menu Apps section, breadcrumb and bookmarks.

Example manifest

{  "id": "acme-maintenance-app",  "type": "app",  "name": "Maintenance",  "info": {    "description": "Work orders and machine downtime",    "version": "0.3.2",    "logos": { "small": "img/logo.svg", "large": "img/logo.svg" }  },  "includes": [    {      "type": "page",      "name": "Work orders",      "path": "/a/acme-maintenance-app/orders",      "addToNav": true,      "defaultNav": true,      "icon": "apps",      "role": "Viewer"    },    {      "type": "page", "name": "Open", "addToNav": true,      "path": "/a/acme-maintenance-app/orders/open"    }  ],  "ui": {    "accent": "#5794f2",    "show": { "menu": true, "dock": true },    "pages": {      "orders": {        "description": "Open and closed work orders"      },      "orders/open": { "description": "Work orders not closed yet" }    }  }}

Where each field shows up

FieldStatusUsed for
nameExistsSwitcher row, Apps card, menu rail, breadcrumb badge
info.descriptionExistsApps card and switcher subtitle
info.versionExistsVersion label on the Apps card
info.logos.smallExistsApp tile in the dock, switcher and menu, tinted with the accent
includes[].name / pathExistsPages and sub pages: menu, page cards, bookmarks in the dock, breadcrumb
includes[].addToNavExistsWhether the page is listed in the menu pane
includes[].defaultNavExistsPage that opens when the app is chosen
includes[].role / actionExistsHides pages the user is not allowed to open
ui.accentNewDefault colour of the app: selected bar, bookmarks group and breadcrumb badge. Setup can change icon and colour for the organisation
ui.showNewStarting value of "Show in menu" and "Show in dock"
ui.pages.<path>.descriptionNewOne-line text on page and sub page cards. The key is the path after /a/<app-id>/
includes[].path nestingExistsA page whose path sits under another page's path is its sub page (flag grafana.pluginPathNesting, experimental, off by default). Replaces the old ui.pages.<id>.children labels
backend CheckHealthExistsApp health right after Enable and in Manage. Only for apps with a backend; Grafana answers the health call only while the app is enabled in its plugin settings
ui.selfTestsNewSelf-tests the app offers at Initialize and Validate. Contract not designed
ui.migrationsNewWhether the app owns database tables, and how it reports and runs pending migrations. Contract not designed

Open questions

Where does the extra "ui" block live?Inside plugin.json or in a separate manifest file. Not verified whether Grafana accepts unknown keys in plugin.json.
How does an app offer self-tests and migrations?The lifecycle needs both. ui.selfTests and ui.migrations are placeholders; the contract with the app is not designed.
Where are the choices stored?Per user or per organization. This decides whether everyone sees the same dock and menu.
Which icon format?Grafana icon names, as in includes[].icon, or the app's own SVG. Mixed use needs one rule.
